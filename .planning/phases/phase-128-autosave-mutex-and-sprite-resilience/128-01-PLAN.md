# Plan 128-01: Blindagem Arquitetural de Auto-Save, Prevenção de Esgotamento de Sockets HTTP e Resiliência Definitiva de Outfits e Movimentação

## Objetivo
Diagnosticar a causa raiz da quebra recorrente de outfits/montarias e congelamento de movimentação após alterações no cliente, eliminar os disparos concorrentes de requisições de persistência ao banco de dados SQLite, implementar mutex e throttle no auto-save e blindar o carregador de imagens contra timeouts transitórios de conexões HTTP.

## Tarefas
- [x] 1. Investigar a causa raiz do desaparecimento de sprites e travamento de movimento no código recente.
- [x] 2. Identificar o disparo em massa de `POST /api/characters/[id]/save` no cleanup do `useEffect` de auto-save a cada passo do personagem.
- [x] 3. Refatorar o auto-save em `GamePrototype.tsx`:
  - `latestSaveStateRef` para leitura atômica e síncrona sem re-execuções de hook.
  - Mutex lock (`isSavingRef`) prevenindo concorrência.
  - Throttle de 10s (`lastSaveTimeRef`) com bypass para logout/switch forçado (`force = true`).
  - Remoção total de `saveProgress()` da função de desmontagem do efeito.
  - Dependência estrita do efeito em `[onlineCharacter?.id, saveProgress]`.
  - Desaceleração do polling de `/api/config` para 60s.
- [x] 4. Blindar `outfitRecolor.ts` com retentativa resiliente (`failedImageAttempts`, `canRetryImage`, `isImagePermanentlyFailed`).
- [x] 5. Criar suíte de testes Vitest `tests/phase128-autosave-mutex-and-sprite-resilience.test.ts` validando todas as novas garantias.
- [x] 6. Validar com `npm run typecheck` (0 erros) e suíte de testes.
