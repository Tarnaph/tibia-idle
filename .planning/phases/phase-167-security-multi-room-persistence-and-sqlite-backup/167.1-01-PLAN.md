# Phase 167.1 Plan: Bloco 1.1 - Concorrência Transacional Otimista, Blindagem de XP WebSocket, Reconciliação 409 e Sandbox de Testes

## Objetivo
Atender com precisão e profundidade técnica os 6 requisitos complementares do Bloco 1:
1. Fechar a brecha de ganho de XP livre via WebSocket no handler `player:syncProgress` de `ThaisCityRoom.ts`.
2. Implementar controle de concorrência otimista (OCC) transacional no banco de dados via `saveVersion` no Prisma, com proteção total de rollback para skills e inventário.
3. Corrigir o defeito de limpeza no Map de `CharacterSaveLockManager.ts` (comparação incorreta de referências).
4. Implementar o ciclo completo de versionamento com status `409 Conflict` e reconciliação no cliente (sem reenvio de dados obsoletos).
5. Validar rigorosamente o inventário contra o catálogo oficial de itens (`equipment.json`), tipos de slot e quantidades plausíveis (equipamentos max 1, stackables max 100).
6. Isolar 100% os testes e o script de backup para utilizarem exclusivamente banco temporário (`test.db`) e diretório temporário (`test-backups/`), garantindo que o banco e backups reais nunca sejam tocados.
7. Monitor Colyseus seguro por padrão (`404 Not Found` caso credenciais não sejam explicitamente configuradas no `.env`).
