# Plan 152-01: Recuperação Definitiva do Banco SQLite, Desrastreamento no Git e Blindagem de Deploy

## Objetivo
Eliminar em definitivo o erro `database disk image is malformed (extended_code: 11)` na VPS, restaurar 100% dos dados dos jogadores a partir do backup saudável `/root/test_recovery/recovered.db` (onde todas as contas e personagens estão íntegros e verificados), desrastrear `prisma/dev.db` do Git (`git rm --cached`) e blindar o `.gitignore` e scripts de deploy para que comandos `git reset --hard` nunca mais toquem ou sobrescrevam o banco de dados.

---

## Tarefas de Implementação

### 1. Desrastreamento de Banco no Git & Blindagem de .gitignore
- Executar `git rm --cached prisma/dev.db` para desvincular o binário do banco do repositório Git.
- Atualizar `.gitignore` adicionando explicitamente:
  - `prisma/*.db`
  - `prisma/*.db*`
  - `dev.db*`
  - `*.sqlite`
- Isso impede que qualquer commit, pull ou `git reset --hard` na VPS altere o arquivo de banco de produção.

### 2. Restauração e Sincronização Segura do Banco na VPS
- Script de restauração via SSH (`scratch/execute-phase152-recovery.mjs`):
  1. Parar todos os processos PM2 (`pm2 stop all`).
  2. Criar backup de segurança carimbado da pasta de banco na VPS.
  3. Copiar `/root/test_recovery/recovered.db` (que contém todas as 5 contas e todos os personagens intactos: `Grievous`, `Godness`, `Lobster`, etc.) para `/root/tibia-idle/prisma/dev.db`.
  4. Remover arquivos residuais de log de transação desincronizados: `rm -f /root/tibia-idle/prisma/dev.db-wal /root/tibia-idle/prisma/dev.db-shm`.
  5. Configurar pragmas resilientes no SQLite:
     `PRAGMA journal_mode = WAL; PRAGMA busy_timeout = 10000; PRAGMA synchronous = NORMAL; VACUUM; PRAGMA integrity_check;`
  6. Garantir symlink canônico `/root/tibia-idle/dev.db -> /root/tibia-idle/prisma/dev.db`.
  7. Reiniciar processos PM2 (`pm2 start all`).

### 3. Blindagem do Script de Deploy (`scratch/deploy-to-vps.mjs`)
- Blindar o script de deploy na VPS para que:
  - Faça backup automático de `prisma/dev.db` antes de qualquer ação.
  - Como `dev.db` não estará mais no git, o `git reset --hard origin/main` não tocará em `prisma/dev.db`.
  - Mesmo assim, adicionar verificação de integridade antes e depois do restart do PM2.

### 4. Blindagem de Testes e Validação
- Criar teste `tests/phase152-sqlite-integrity-and-deploy-shield.test.ts`:
  1. Valida que `.gitignore` contém regras que ignoram `prisma/*.db*` e `dev.db*`.
  2. Valida que `prisma/dev.db` não está no índice do git (`git ls-files prisma/dev.db` é vazio).
  3. Valida integridade do banco local com `PRAGMA integrity_check`.
- Executar teste de login na VPS com `designerosa@outlook.com`.
- Executar `npm run typecheck` e suite de testes.
