# Phase 222: Persistent Hotkeys & Slot Configurations for Party Alts

## Contexto & Problema
O usuário configurou poções, magias e regras condicionais (ex: cura quando HP <= 80%) para personagens secundários da party (alts como Wolfy e Cerberus), mas notou que as hotkeys de membros da party não estavam sendo salvas nem restauradas após recarregar/relogar, salvando apenas as do líder principal.

### Diagnóstico de Causas Raízes
1. **Omissão no Autosave Periódico de Alts (`GamePrototype.tsx`):**
   O loop de `ownedAlts` montava o payload POST para `/api/characters/${alt.id}/save` com level, exp, hp, mana, skills, inventory, outfit, mount... mas **não incluía `hotbar: alt.hotbar` nem `hotbarConfigs: alt.hotbarConfigs`**.
2. **Ausência de Hidratação em `hydrateDbCharacter` (`GamePrototype.tsx`):**
   Quando a conta carrega seus personagens via `/api/characters`, `hydrateDbCharacter` criava cada alt a partir de `createCharacter`, mas nunca lia `c.hotbarJson`. Consequentemente, o `savedPool` ficava com a hotbar vazia default para todos os alts.
3. **Falta de `saveVersion` nas Ações Pontuais de Hotbar (`GamePrototype.tsx`):**
   Tanto `handleSetHotbarAction` quanto `handleReorderHotbar` disparavam um POST imediato para `/api/characters/${targetChar.id}/save`, porém sem enviar `saveVersion`. Como a rota exige estritamente `saveVersion >= 1`, a requisição era rejeitada com HTTP 400 (`SAVE_VERSION_REQUIRED`).
4. **Sobrescrita Destrutiva em Atualizações Parciais (`characterService.ts`):**
   Ao receber `data.hotbarConfigs` sem `data.hotbar` (ou vice-versa), o backend substituía `hotbar` por `[]` ao invés de mesclar com o `existing.hotbarJson`.

## Plano de Ação
1. **Atualizar `hydrateDbCharacter` em `GamePrototype.tsx`:**
   - Parsear `c.hotbarJson` (ou ler `c.hotbar`) e atribuir `ch.hotbar` e `ch.hotbarConfigs`.
2. **Atualizar `saveProgressRef` (`ownedAlts` loop) em `GamePrototype.tsx`:**
   - Incluir `hotbar: alt.hotbar` e `hotbarConfigs: (alt as any).hotbarConfigs` no corpo JSON enviado para a API.
3. **Atualizar `handleSetHotbarAction` e `handleReorderHotbar` em `GamePrototype.tsx`:**
   - Enviar `saveVersion: targetVersion` extraído de `characterSaveVersionsRef.current.get(targetChar.id) || (targetChar as any).saveVersion || 1`.
   - Atualizar `characterSaveVersionsRef` após resposta de sucesso ou 409 conflito.
   - Sincronizar `savedPool` e `savedPoolRef.current` para o personagem alvo em memória.
4. **Atualizar `saveCharacterProgress` em `characterService.ts`:**
   - Mesclar com `existing?.hotbarJson` para garantir que atualizações que incluam apenas `hotbar` ou apenas `hotbarConfigs` preservem o conteúdo anterior.
5. **Criar Suíte de Testes Automatizada:**
   - `tests/phase222-party-alts-hotbar-persistence.test.ts`.
6. **Verificação & Deploy:**
   - `npm run typecheck` (0 erros).
   - `npm run test -- tests/phase222-party-alts-hotbar-persistence.test.ts` (100% aprovação).
   - Git commit convencional e deploy na VPS `187.7.16.210`.
